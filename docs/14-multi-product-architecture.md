# 学习框架、多语言产品与课程拆分

2026-10-08 用户新增要求：分离学习框架、特定语言产品及课程到独立仓库；新增粤语产品 Hargow，品牌文案「每日一啖，粤讲粤好」，复用框架和后端数据库，使用不同域名与入口。本文件是迁移设计与实施范围，不表示仓库拆分或生产多产品部署已经完成。

## 仓库职责

用户已确认公开范围与产品/课程仓库命名；通用框架命名为 Chef，仓库 `chef`。现有公开 `brioche` 保留历史和生产入口。

| 仓库 | 所有的内容 | 不拥有的内容 |
| --- | --- | --- |
| `chef` | 身份服务、学习 API、数据库迁移、语言中立课程契约与生成器、课程解释器、学习/复习/后台、播放器、通用 Web 组件、框架测试与运维工具 | Brioche/Hargow 品牌、某一种语言的正式课程或私有声音密钥 |
| `brioche` | 法语产品装配、品牌/主题/首页文案、图标、产品配置、部署入口和兼容测试 | 通用业务逻辑的第二份副本、正式课源真源 |
| `brioche-courses` | 法语课源、目录、原创课程插图、角色与公开授权说明、固定版本引用、课程质量检查 | 框架实现、账号数据、提供方密钥、私有配音包 |
| `hargow` | 粤语产品装配、品牌/主题/文案/图标、域名配置、部署入口和产品测试 | 法语业务假设或复制的后台实现 |
| `hargow-courses` | 粤语情境课程、粤拼/注音、词汇语法、角色和语音生成脚本数据、固定目录与素材授权 | 通用业务实现、真实账号、未经授权的参考声音 |

框架允许内部 Rust/Web/契约 workspace，但跨仓库依赖固定已验证的提交或发布版本，不能在生产跟随 `main`。两个产品使用同一框架版本时，构建必须从同一份框架源码产生；课程发布另固定课源提交和框架契约版本。抽取期间允许框架保留旧的内部包名，正式对外接口迁移再改名，不用大规模字符串替换作为去品牌化的证明。

用户进一步要求产品仓库尽可能轻量。最终产品仓库只保留产品配置、主题/字体/图标、文案、页面装配入口、部署装配和少量产品兼容测试；不保留课程真源、数据库迁移、身份/学习业务、通用管理员页面或播放器副本。共用功能修复只在Chef做一次，产品通过固定版本升级获得。默认使用配置和少量明确扩展点完成产品差异，不能把整套框架复制到产品目录再称轻量。

Git子模块只是固定框架源码依赖的交付方式，其文件计入Chef的所有权；最终产品自己的已跟踪实现不得继续包含原server/migration/通用Web业务副本。构建或运行时所需大小与产品仓库拥有的代码量分别记录，不能仅靠减小clone下载量满足轻量要求。

## 产品入口与共用数据库

产品由服务器配置的域名映射确定。请求不能通过 query/body 中的任意 `productId` 选择其他产品；网关必须移除客户端伪造的内部产品头，API 自身仍验证产品上下文。未知域名拒绝，不回退到 Brioche。SSR、公共目录、媒体、私有路由、Origin/CSRF、缓存键均带同一个已验证上下文。

复用现有 PostgreSQL 数据库；增加固定 `products` 与产品上下文，不为 Hargow 新建一份未经管理的独立业务库。当前 `content_state` 的 singleton、全局课源/目录编号、角色/录音、学习会话、复习去重、个人设置及后台权限都需要迁移为明确产品范围。唯一约束和外键要包含产品维度，不能只在页面隐藏其他语言。

用户已确认共用身份，学习设置、进度、收藏和复习按产品隔离。即使共用账号，也不自动给管理员两个产品的管理权限：产品授权须明确。不同域名使用各自 host-only cookie 与精确 Origin；共享账号数据库不等于跨域 Cookie 或自动单点登录，SSO 如需支持另做明确流程。

## 独立身份服务

身份服务属于 Chef 仓库，独立构建和运行；学习 API 不再直接读取密码哈希或修改邀请/恢复 token。身份服务拥有账号、密码哈希、会话、邀请/恢复、登录限流、全局账号资料及产品成员/管理员授权；学习 API 拥有按产品的学习设置、课程及学习事实。

同一 PostgreSQL 内划分身份与学习 schema、独立数据库角色和最小权限。学习数据使用稳定 user ID 引用身份，账号移除/停用由身份服务负责协调，不通过共享数据库写权限绕过服务边界。旧身份表迁移必须保持账号 ID、密码哈希、有效会话与 token 的真实语义，迁移前在隔离数据库验证，不直接重建生产账号。

第一阶段采用每个产品同源 `/api/auth/*` 反代到身份服务；该服务只接受网关和配置中确认的产品/Origin。Cookie 为当前产品域名的 host-only、Secure、HttpOnly，会话固定产品 audience。学习 API 通过内网验证/内省会话，确认账号状态、产品身份与管理权限；不把客户端自报 user ID/product ID 当身份。内省失败拒绝私有请求，不缓存失效管理员权限无限延长会话。JWT 或跨域 SSO 均不是此次必须先引入的前提。

邀请/密码恢复链接选择明确产品域名，禁止任意 return URL；密码恢复和全局账号停用使所有产品旧会话失效，单产品退出只关闭相应产品会话。账号后台迁移为身份服务 API，课程/配音后台仍使用产品学习 API；审计保留真实 actor 和产品范围。所有原 Origin/CSRF、缓存隔离、限流与重放保护都需双服务回归。

迁移将现有所有业务行归入 `brioche`，保持主键、课程 revision、generation、首次完成、历史收藏来源、原幂等键和发布/声音审计。Hargow 从自己的空目录和授权开始。固定学习版本与撤回语义保持，切换产品不能把待确认原请求发送到另一个入口。标签页草稿、身份广播、复习恢复和媒体缓存均加入产品标识。

媒体使用产品授权与固定资产引用。共用文件存储允许物理按哈希去重，但哈希相同不能绕过产品权限；私有试听、参考录音能力地址和作者包仍需当前产品及管理员检查。生产数据库秘密、TTS 密钥与私有配音证据不进入任何新公开仓库。

## 语言中立课程与粤语能力

当前已确认的法语绑定包括 `Title.fr`、`GrammarExample.fr`、`CHARACTER_SPEECH_LOCALE = fr-FR`、法语系统音色列表、正文 lang 和相关 UI 文案。新契约以显式目标语言与目标文本替代固定 `fr` 字段；解释语言独立配置。Brioche 的旧 1.0 课程继续通过版本适配器读取，适配后的公开数据和判分结果须与旧版一致，不覆盖已发布源文件。

Hargow 目标语言采用粤语 `yue-Hant-HK`，面向中文学习者；繁体口语正文与中文解释、粤拼分开记录。注音使用结构字段，不能把拼音塞进原句以破坏词音区间或判分。词/语块由作者显式标注 Unicode 范围，粤语分词不能依赖法语的空格算法。等级和单元是产品课程体系，不能把法语 CEFR 标签自动套给粤语；框架允许自定义等级 ID/名称。

声音档案保持角色、音色、参考录音授权、个性、情绪与版本一致性；提供方能力由语言适配器验证。现有法语 Qwen 模型/音色白名单不能直接代表粤语可用。正式粤语生成前需核对模型与粤语音色、做实际试听并保存来源，不能用普通话发音冒充粤语。逐词时间轴也需适配粤语真实模型输出，不能平均分配字数推造时间。

## 实施顺序与验收

1. 对已提交文件做拆分清单，建立框架/产品/课程的所有权边界、依赖方向和排除项；先在本机独立 checkout 中准备仓库，不切换生产。
2. 抽取框架与法语课源；产品依赖固定框架提交。Brioche 从独立课源仓库构建/检查，原生产功能和48课回归通过后才切换。
3. 引入产品配置、语言中立契约与旧版适配器，建立 Hargow 产品壳和课程目录。品牌、PWA、语言标签、首页/后台名称来自产品配置。
4. 在隔离 PostgreSQL 执行真实升级/回滚与双产品测试：相同课 ID/角色 ID 在不同产品合法，跨产品读取/写入/重放/媒体/后台拒绝，目录激活相互独立，历史 Brioche 行全部保留。
5. 完成粤语首个真实场景课与音频试点，再扩展课程；确认 Hargow 的实际域名后添加网关路由。公网 DNS/TLS 仍由用户现有网关处理，不恢复 HTTP30075。
6. 备份并部署共用后端与两个独立产品入口，核对账号决策、Origin、SSR、学习/复习、角色/媒体、后台权限及两个域名行为。真实设备和运维验收属于完整目标，不能以五个仓库创建成功代替。

任何抽取都保留原提交来源说明；不能把复制后的目录宣称已实现框架复用。数据库迁移、生产入口切换与仓库实际提交将在实现清单记录最终证据。
